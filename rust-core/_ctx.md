# rust-core
Слой: БЭКЕНД

## НАЗНАЧЕНИЕ
Библиотека `webinarip-core` публичного проекта `../webinarip/core` (github nilysenok/webinarip, MIT): метаданные записи, HLS, загрузчик, кэш, потоковый микшер, кодировщики. Чистый Rust, кроме статически вшитого LAME.

## КОНТРАКТ
- видео: `video/` — `fmp4` (кадры с метками и ключевым флагом, размер из `tkhd`), `webm` (VP9 + Opus, кластеры с ключевого кадра, Cues), `patch` (сдвиг `tfdt`, длина в `mehd/mvhd`); `deliver` — видео, дорожки участников, `--mp4`; `export` — FCPXML (видео на дорожках 1…N, звук −1…) и EDL CMX3600
- `job::produce(dl, opts, (rec, tracks), prog, cancel, on_start)` — общий путь CLI и serve: одно сведение → файл + Opus-пакеты для видео → видео, дорожки, мультикам
- `Engine` (общий http + AIMD-лимит) → `Download` (загрузка в фоне; `restrict(from,to,slots)` выкидывает лишнее из очереди) → `Render::write_file` (сведение+кодирование, отмена флагом)
- `job::run(Options, render_progress, on_download)` — то же для CLI одним вызовом
- `job::fetch_record`, `record::{parse, select}` (`host`, номера из `--list`), `hls::{parse_master, parse_media}`
- `Progress` — атомарные счётчики для CLI и будущего UI: этап, сегменты, байты, повторы, хеджи, 429, лимит, сведено мс, p50/p99, гистограмма
- форматы: MP3 (LAME, по умолчанию), Opus в Ogg (opus-rs), AAC .m4a (AudioToolbox на macOS, иначе системный ffmpeg), WAV; качество `high` 48 кГц стерео, `low` 16 кГц моно
- кэш: `~/Library/Caches/webinarip/<запись>/<дорожка>/a/NNNNN.m4s`; вывод: `<out>/ГГГГ-ММ-ДД_ЧЧММ <название>/<название>[ отрезок].<ext>`
- session-id только из аргумента / `WEBINARIP_SESSION_ID`, живёт в памяти

## ИНВАРИАНТЫ
- видео не перекодируется: кадры VP9 копируются; `--mp4` — только системный ffmpeg и только по флагу
- видео качается после всего звука (rank = at + 1e7), чтобы первый звук не ждал тяжёлых сегментов
- `remux` и копия дорожек — в два прохода, в памяти один сегмент (пик 239 МБ на всю запись со всем, было 864)
- кадры пишутся в порядке декодирования; метки видео строго возрастают (WebM — миллисекунды)
- нет блокировки головы очереди: декодер сообщает, какой файл ждёт (`Gate::waited`); `rush.rs` раз в 25 мс дублирует его запрос (если старше ½ p50, до 2 дублей) или берёт вне очереди (если в очереди/на повторе) из резерва внутри потолка (256 = 248 + 8), а пока микшер ждёт дольше p50 — новые обычные запросы не стартуют («фокус»)
- ровно один засчитывает сегмент: состояния PENDING/FLIGHT/DONE, проигравший запрос снимается через Notify
- только HTTP/1.1: HTTP/2 в 7,7 раза медленнее (замер 25.09, Python-серия)
- сегменты качаются в порядке общей шкалы времени; повтор возвращается в очередь со своим приоритетом — иначе микшер стоит (найдено 25.09: один повтор в конце очереди = 100 с простоя сведения)
- сегмент пишется через `.part` + rename; наличие файла = сегмент целиком
- сведение = сумма (как amix normalize=0) + лимитер с упреждением 5 мс, потолок 0,95
- декодер читает дорожку как поток без перемотки и ждёт появления файлов — на этом держится сведение во время загрузки
- `record::select`, `timefmt::parse` — ошибки пользователю на английском, понятные без исходников

## ТЕХДОЛГ
- дорожки участников (.m4a) режутся по границам сегментов (~13 с): байты копируются без перекодирования; смещения в FCPXML/EDL это учитывают (`start`/source in)
- EDL — однодорожечный формат: все клипы подряд списком; полная мультикам-раскладка только в FCPXML
- ffmpeg на выводе в null пишет «non monotonically increasing dts» и для исходного fMP4 с сервера — свойство VFR-потока, не перепаковки (проверено 26.09)
- камеры в тестовой записи — 320×180 (SMALL), 25 fps; заявленное в плейлисте 640×480 не соответствует кадрам
- ожидание микшера на реальном сервере не опускается ниже ~1,5× p50: медленный объект медленный для всех запросов (замер 25.09: два дубля одного сегмента вернулись вместе с оригиналом через ~28 с); на моке с зависшим соединением — 1,1× медианы
- метрика «простой» зависит от способа: по файлу (Gate) 11,5–13,7 с = 1,5–1,9× p50 во всех 3 прогонах CLI; по отсутствию движения сведения в интерфейсе 11,1–17,6 с = 1,4–2,1× p50 (2 прогона, один на 2,09×)
- Opus: `use_cbr = true` обязателен — в VBR opus-rs игнорирует битрейт (24 кбит/с → 53–74 кбит/с, замер 25.09)
- частота дорожек только 48 кГц (иначе ошибка); ресемплинга входа нет — на реальных записях другой не встречалась
- AudioToolbox FFI написан вручную (без bindgen); проверен только на macOS arm64

## ПЕЧАТИ
Ъ — качество по умолчанию «речь»: моно 48 кГц, MP3 64 кбит/с (Opus 32, AAC 64); стерео 128 и «расшифровка» 16 кГц — опциями `--quality high|low` (25.09)
Ъ — «фокус» при ожидании микшера — поведение по умолчанию; `WEBINARIP_NO_RUSH=1` отключает дубли и фокус только для диагностики (25.09)
Ъ — LAME с качеством 7 (`Quality::Ok`): 28,6 с против 38,6 с на q5 (замер 25.09), для речи на 128 кбит/с разницы не слышно (25.09)
Ъ — жёсткий потолок 256 соединений (`HARD_CAP`), пользователь может только уменьшить; соблюдение 429: лимит ×0,5 + пауза Retry-After; «только для записей, к которым у вас есть права» — в коде и README (25.09)
Ъ — форматы: MP3 по умолчанию (LAME статически), `--opus`, `--aac` (AudioToolbox / системный ffmpeg); видео — WebM по умолчанию, `--mp4` только через системный ffmpeg; отдельные дорожки — .m4a без перекодирования (25.09)
Ъ — публичный проект без «MTS» в названии и без упоминаний ИИ; автор Nikita Lysenok; чистая история, канон в него не попадает (25.09)
Ъ — распознавание речи (этап 9): whisper.cpp, модель large-v3-turbo; выбран по заранее записанному критерию скорости: 1,07× медленнее mlx-whisper < порога 1,5× (замер 26.09); встраивается в бинарник, 5 платформ, без Python (26.09)

## НЕ ТРОГАТЬ
- `decode.rs`: сдвиг позиций по `tfdt` первого фрагмента — symphonia его не учитывает, без сдвига `--from/--to` дают тишину
- `cache.rs`: уникальное временное имя в `write_atomic` — общий `.part` роняет загрузку при дублях сегмента
- `fetch.rs`: приоритетная очередь с исходным приоритетом при повторе — замена на «задача на сегмент + семафор» вернёт простой сведения
- `mix.rs`: `starts_at` у входа — без него микшер ждёт первую порцию дорожки, которая начинается через час, и встаёт
- `encode/aac.rs`: `BufferList` вложенной структурой — плоская раскладка ломает выравнивание указателя (AudioBufferList)

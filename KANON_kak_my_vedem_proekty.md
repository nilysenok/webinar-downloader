# КАНОН · как мы ведём проекты в md

Одна страница. Кладётся в любой новый проект, по ней Claude Code разворачивает систему и работает в каждой сессии.

---

## На пальцах

1. Всё, что мы знаем о проекте, лежит в **md-файлах внутри репозитория**, рядом с кодом. В голове и в чате ничего не хранится.
2. У каждого модуля свой файл **`_ctx.md`**. Там и только там живёт правда о модуле: что он делает, что сломано, что решено, что запрещено трогать.
3. **`ROOT.md`** — общая сводка по проекту. Она **собирается автоматически** из всех `_ctx.md`, руками её не правим.
4. **Дашборд `dashboard.html`** — картинка для глаз. Тоже собирается автоматически, одной командой. Это визуализатор, не редактор.
5. Правило конвейера: **правим только md → собираем → смотрим html.** Обратного пути нет.

```
<модуль>/_ctx.md  ─┐
<модуль>/_ctx.md  ─┼─→  cargo xtask  ─→  ROOT.md + dashboard.json  ─→  dashboard.html
<модуль>/_ctx.md  ─┘        (сборщик + валидатор)
```

---

## Файлы

| Файл | Что это | Кто правит |
|---|---|---|
| `CLAUDE.md` | правила работы для каждой сессии Claude Code | я, редко |
| `spec.md` | законы системы, словарь, лимиты | я, редко |
| `<модуль>/_ctx.md` | **канон модуля**, единственный источник правды | Claude Code по ходу работы |
| `ROOT.md` | сводка по всем модулям | **только сборщик** |
| `arhiv.md` | закрытое и решённое: `ДД.ММ · [модуль] · что` | дописывается снизу |
| `roadmap.md` | этапы проекта (из него рисуется степпер в дашборде) | я + Claude Code |
| `dashboard.html` | визуализация | **только сборщик** |

Больше служебных файлов не заводим.

## Шаблон `_ctx.md`

```markdown
# <имя модуля>
Слой: БЭКЕНД | ФРОНТЕНД

## НАЗНАЧЕНИЕ
1–3 строки: зачем модуль существует.

## КОНТРАКТ
Что отдаёт наружу: функции, CLI-флаги, эндпоинты, формат данных.

## ИНВАРИАНТЫ
- что никогда не должно ломаться

## СТАТУС
стабильно | в работе | чинится | заморожен

## ЗАДАЧИ
- [ ] 🔴 ДД.ММ задача со сроком
- [ ] задача без срока

## ТЕХДОЛГ
- что не трогаем сейчас и ПОЧЕМУ

## ПЕЧАТИ
Ъ — принятое решение, не пересматривать (это ADR)

## ЖДУНЫ
⏳ кто/что → чего ждём, с какого числа

## ОТКРЫТО
❓ вопрос ко мне, блокирующий работу

## НЕ ТРОГАТЬ
- место в коде + почему правка опасна
```

Если модуль и бэк, и фронт (например, веб-скринер), `_ctx.md` делится на две половины. В дашборде слои показаны раздельно: **ФРОНТЕНД** и **БЭКЕНД**.

## Законы

1. **Закон канона.** Статус факта живёт только в `_ctx.md` его модуля. ROOT и дашборд — производные. При противоречии прав модуль.
2. **Закрытое только в архиве.** В живых файлах нет ✅-строк: закрыл, значит, строка уехала в `arhiv.md`.
3. **Ничего не выдумывать.** Неизвестное оформляется как `❓` в ОТКРЫТО, а не как догадка в каноне. Спорный факт несёт источник: `(лог CI)`, `(замер 23.09)`.
4. **Одна черепаха.** Одна крупная стройка за раз. Остальное ждёт в ТЕХДОЛГЕ.
5. **HTML руками не правится.** Дашборд показывает неправду? Чиним md и пересобираем.
6. **Печать — это приговор.** `Ъ —` не пересматривается без моей явной команды. Снять печать можно только записью в архиве с датой и причиной.
7. **Критерий остановки пишется заранее.** Любая гипотеза получает порог до эксперимента («меньше 0.5 bps чистыми — закрываем»). Результат записывается любым, в том числе отрицательным.

## Лимиты

- файл кода ≤ **200** строк, функция ≤ ~40
- `_ctx.md` ≤ **150** строк (разросся — делим модуль)
- модулей на уровень ≤ **10**
- задач в модуле ≤ **25**

Сборщик проверяет лимиты сам (`cargo xtask --check`), это же работает как CI.

## Ритм сессии

**Начало.** Claude Code читает `CLAUDE.md` → `spec.md` → `ROOT.md` → `_ctx.md` нужного модуля. НЕ ТРОГАТЬ и ПЕЧАТИ — запреты.

**По ходу.**
- Одна сессия — один модуль.
- Сначала план, потом код. Тесты обязательны.
- Нашёл баг или принял решение — сразу в `_ctx.md`, не «потом».

**Конец.**
1. Обновить `_ctx.md` затронутых модулей.
2. Закрытое перенести строкой в `arhiv.md`, решения записать печатью, вопросы — в ОТКРЫТО.
3. `cargo xtask`: пересобрать ROOT и дашборд, валидатор зелёный.
4. **Коммит.** Рабочая копия чистая.
5. **Push** в удалённый репозиторий (бэкап).
6. Контекст раздулся? Делаем `/clear`: всё важное уже в md.

## Уроки Hustle (чтобы не наступать второй раз)

- **Диск без копии — не диск.** Код на GitHub (приватный репо), данные копируются на второй носитель. exFAT для рабочего диска — плохой выбор.
- **Mac засыпает — запись умирает.** Длинные прогоны только через скрипт с `caffeinate`, и крышку не закрывать.
- **Скрипт вместо «ассистент, запусти потом».** Claude Code сам не просыпается. Всё, что должно выполниться без меня, — в `scripts/*.sh`, одной строкой.
- **Каждый прогон в свою папку с датой.** Иначе следующий перезапишет предыдущий.
- **Сначала потолок, потом правда.** Первая цифра всегда оптимистична. Проверяем задержку, глубину и налив, прежде чем радоваться.
- **`/clear` без страха.** Если канон ведётся честно, новая сессия восстанавливается за одну команду.

## Готовые промпты

**Развернуть канон в новом или старом проекте:**
```
Разверни в этом репозитории систему КАНОН по файлу KANON_kak_my_vedem_proekty.md.
Этап 1 — разведка, ничего не меняя: что за проект по коду, модули (≤10) с делением на ФРОНТЕНД/БЭКЕНД, что работает, что сломано, незавершённое, файлы >200 строк, вопросы ко мне списком. Стоп, жди моего «да».
Этап 2 — создай CLAUDE.md, spec.md, arhiv.md, roadmap.md, <модуль>/_ctx.md по шаблону, сборщик xtask (md → ROOT.md + dashboard.json → dashboard.html, валидатор --check). Неизвестное — в ❓, не выдумывай.
```

**Начать сессию после `/clear`:**
```
Прочитай CLAUDE.md, ROOT.md и _ctx.md модуля <имя>. Скажи в 5 строках, где мы и что дальше.
```

**Закрыть сессию:**
```
Закрываем сессию: обнови _ctx.md затронутых модулей, закрытое — в arhiv.md, решения — печатями, вопросы — в ОТКРЫТО. cargo xtask, коммит, push. Покажи, что изменилось в ROOT.md.
```

**Тест восстановления (раз в месяц, 10 минут):**
```
Не читая код, только по md: что сейчас главное, какие три ближайших задачи со сроком, что запрещено трогать?
```
Ответы верны — система работает. Нет — в md не хватает контекста, дописываем.

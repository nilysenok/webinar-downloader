# downloader
Слой: БЭКЕНД

## НАЗНАЧЕНИЕ
Скачивает запись вебинара MTS Link в режиме «только аудио» (MP3), «видео + аудио» или «только видео» (MP4)
и складывает итог в папку загрузки. Не знает про HTTP-сервер и UI.

## КОНТРАКТ
- всё, что зависит от ОС, — в `osdeps.py`: `font()` (шрифт с кириллицей: Arial / Arial·Segoe UI / DejaVu·Liberation·Noto, иначе `fc-match`; нет — общий экран без подписей), `filter_path()` (путь для фильтра ffmpeg, `C\:` экранирован), `Awake` (не спать: caffeinate / SetThreadExecutionState / systemd-inhibit), `reveal()` (Finder / Проводник / xdg-open)
- `Job(url, mode, quality, streams, workers, gallery=True)` + `await run(job)` — выполняет задачу; наружу не бросает, итог в `job.status / error / outputs / log`
- статусы: `queued → meta → download → mix → mux → done | error | cancelled | interrupted`
- `await analyze(client, url)` → `{sid, title, date, duration, tracks}`; у дорожки `variants`, `has_audio`, `kind`; в `variants` только потоки, где init-сегмент содержит видео, размер — настоящий из `tkhd` (`boxes.video_size`)
- в режимах с видео итог — один файл `<название> — общий экран.mp4` (отдельные видео каждого — только с `gallery=False` / `--no-gallery`): живая раскладка как в Zoom — в кадре те, у кого сейчас камера, и те, кто говорил за последние 20 с (появляется за 1 с до речи); говорящий — в зелёной рамке, без камеры — тёмная плитка с крупным именем, никого — заставка с названием; сетка по числу людей, до 3×3, порядок по первому появлению, состав держится ≥ 10 с; звук — общий микс (в «Только видео» тоже; отдельные файлы при `--no-gallery` в «Только видео» без звука); H.264 VideoToolbox `-q:v 50`
- общий экран по модулям: `speech.py` (речь: громкость дорожки > −40 дБ по окнам 0,5 с, паузы ≤ 1,5 с склеены, всплески < 1 с выброшены) → `layout.py` (отрезки с постоянным составом, чистая логика) → `tiles.py` (граф отрезка) → `gallery.py` (отрезки по 3 параллельно, `seg_NNNN_<хеш>.mp4` не пересобираются, склейка concat + звук)
- `job_folder(job)` → `downloads/ГГГГ-ММ-ДД_ЧЧММ <название>/`, промежуточные — `job.work` = `…/_work/`
- `job.cancel = True` — мягкая отмена: воркеры и ffmpeg останавливаются, сегменты остаются
- CLI: `.venv/bin/python -m downloader.cli <ссылка> [--mode audio|av|video] [--quality best|480] [--workers 64] [--no-gallery]`
- вход API MTS Link: `GET /api/eventsessions/<id>/record?withoutCuts=false` (открытые записи — без авторизации)

## ИНВАРИАНТЫ
- качаются только нужные HLS-рендишны (аудио `a1/…`, видео — вариант по качеству); mp4 целиком не качается
- сегмент пишется через `.part` + rename — недокачанный файл никогда не лежит под финальным именем
- перезапуск той же задачи не качает сегменты, уже лежащие в `_work/`
- видео не перекодируется (`-c copy`); в режиме av звук — кусок общего микса с `relativeTime` потока
- ffmpeg пишет во временный `*.part.*`; при сбое/отмене он удаляется
- `run()` никогда не бросает исключений наружу
- видео или нет — только по init-сегменту (`hdlr` = `vide`), не по RESOLUTION из master; при склейке поток без видео пропускается с предупреждением, задача не падает
- stderr ffmpeg читается параллельно с прогрессом — полный канал stderr останавливает ffmpeg
- `run()` первым делом поднимает мягкий лимит открытых файлов до 10240 (`limits.py`): из Finder/Терминала macOS даёт 256, а 256 потоков = 256 сокетов + 256 `.part`; не хватает — предупреждение в логе задачи

## ТЕХДОЛГ
- Windows и Linux проверяются только в GitHub Actions (тесты + запуск start.bat / start.sh с нуля); вживую на них загрузку настоящей записи не гоняли (29.09)
- определение экрана — эвристика по модулю `screensharing*` в eventLogs; в тестовой записи экрана не было, проверить не на чем
- RESOLUTION в master-плейлисте врёт (640×480 у всех, реально 320×180 / 480×270 / 640×360 / 1280×720, и 640×480 у дорожек без камеры): разбор записи делает 2 лишних запроса на дорожку (плейлист + init), 4,5–6 с вместо ~1 с (28.09)
- общий экран: если камера человека шлёт чёрные кадры (ИФР: участник в первые минуты, тестовая запись: другой на 55-й), плитка чёрная с именем внизу, а не «без камеры» с крупным именем — чёрное не распознаём: проход blackdetect (1 кадр/с, 320×180) на ИФР — 204 с, «только ключевые кадры» — 171 с (у VP9 MTS Link ключевой почти каждый кадр), VideoToolbox VP9 не декодирует; критерий «≤ 2 мин» не выполнен (замер 29.09). Сама детекция точна: камера участника 0:11–2:30 и 2:49–6:39
- общий экран: речь — по порогу громкости своей дорожки; громкий шум у молчащего человека тоже выведет его в кадр (порог выбран по замеру 28.09, на 2 записях)
- общий экран перекодируется: ~28× реального времени (105 мин за 3 мин 45 с, M2 Max, 28.09), грузит CPU; в `ui/` не отключается (Ъ ui 28.09) — только `--no-gallery` в CLI
- ретраи: 6 попыток с паузой до 20 с; при 403/404 — сразу ошибка. Порог подобран без замеров потерь
- `_work/` занимает ~2× аудио (917 МБ на запись 24554640907, 25.09): сегменты + склеенные `a.mp4`; сегменты нужны для докачки, чистится кнопкой «Удалить промежуточные»
- RAM процесса растёт с числом потоков: 120 МБ на 64, 310 МБ на 256 (замер 25.09) — терпимо, но держать в уме
- скорость упирается в канал пользователя: на 256–320 потоках 5,0–5,5 МБ/с при потолке канала 4,8–6,1 МБ/с на одно соединение к Cloudflare (замер 25.09); выше не прыгнуть без другого канала
- `bytes_total_est` — оценка по среднему размеру сегмента, точного размера заранее нет (HEAD на тысячи сегментов дорого)

## ПЕЧАТИ
Ъ — загрузчик работает на macOS, Windows и Linux; платформенный код — только в `osdeps.py`, остальной код от ОС не зависит (29.09)
Ъ — общий экран всех камер (как галерея Zoom) — по умолчанию в режимах с видео, со общим звуком; `--no-gallery` отключает (28.09)
Ъ — с общим экраном в папке один видеофайл — общий экран со звуком; отдельные видео каждого только без общего экрана (29.09, владелец: «нужно одно видео общий экран»; отдельные файлы в «Только видео» беззвучны и путали)
Ъ — запись = параллельные дорожки участников (18 в тестовой записи); склейка только сведением amix по relativeTime, concat нельзя (25.09)
Ъ — в amix обязателен `normalize=0`, иначе итог тихий: amix делит громкость на число входов (25.09)
Ъ — папка на каждую загрузку: `downloads/ГГГГ-ММ-ДД_ЧЧММ <название>/` по моменту загрузки, внутри итог и `_work/`; повтор той же записи не перезаписывает прошлую (25.09)

## НЕ ТРОГАТЬ
- число соединений к `events-delivery-records.webinar.ru` суммарно не выше ~320: на 384 — 20% таймаутов, на 512 — 85–88% ошибок (ConnectTimeout/ReadTimeout), скорость 0,4 МБ/с (замер 25.09, воспроизведено дважды)
- HTTP/2 не включать: 256 потоков по HTTP/2 = 0,65 МБ/с против 5,04 по HTTP/1.1 (замер 25.09) — все запросы идут через одно TCP-соединение
- `media.mix_filter`: `normalize=0` и `adelay=…:all=1` — без них тихий звук или сдвиг только левого канала
- `pipeline._drain`: запись сегмента через `.part` + `replace` — на этом держится докачка
- `gallery.render`: `-reinit_filter 0` перед каждым видеовходом — MTS Link меняет размер кадра внутри потока, без флага граф пересобирается на каждую смену, источники color начинают с нуля и сборка встаёт (ИФР, 28.09; тест `test_frame_size_change_inside_stream`)
- `pipeline.job_folder`: если `job.folder` уже задан, он возвращается как есть — иначе перезапуск уедет в новую папку и докачка сломается
- `limits.raise_open_files()` в начале `_run`: без него дашборд из `start.command` падает `[Errno 24] Too many open files` на первом сегменте при 256 потоках (29.09, воспроизведено: лимит 256 → ошибка, с подъёмом → 315 сегментов за 45 с; тест `test_limits.py`)

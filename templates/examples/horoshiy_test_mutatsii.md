# Хороший тест-мутация · образец (Ж-004 2.7)

Тест-мутация проверяет не «код работает», а «сломанный код не пройдёт». Признаки хорошего:

1. **Назван по инварианту, а не по функции.** `test_normalize_off_and_offsets` (`tests/test_media.py`) — про громкость и
   сдвиг каналов в сведении, а не «test_mix_filter».
2. **Падает на конкретной мутации из `kanon/pravila/mutations.md`.** M1 (`normalize=0` → `1`) и M2 (без `:all=1`) —
   этот тест падает на обеих (прогон 27.10, `docs/otchety/mutations_2026-10-27.tsv`).
3. **Проверяет наблюдаемое значение**, а не повторяет код: фильтр содержит `normalize=0` и `adelay=…:all=1` для каждой дорожки.
4. **Не тавтологичен.** Плохой пример — `tests/test_downloader.py:84`: `assertEqual(job_folder(a), Path(a.folder))`.
   После мутации M6 `job_folder` сам перезаписывает `a.folder` и возвращает его же — сравнение всегда совпадает,
   мутация не ловится. Хороший — сравнить с путём, сохранённым до вызова.
5. **Проверен механически:** мутация применяется в копии, тест красный; без мутации — зелёный. Результат — в отчёте PR.

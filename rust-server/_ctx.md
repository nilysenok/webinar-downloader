# rust-server
Слой: БЭКЕНД

## НАЗНАЧЕНИЕ
Режим `webinarip serve` публичного проекта `../webinarip/server`: axum на 127.0.0.1, очередь задач, история, отдача растущего аудио плееру, встроенный интерфейс из `ui/`.

## КОНТРАКТ
- `webinarip serve [--port 5040] [--out ~/Downloads/webinarip] [--no-open] [--cache-dir]`; порт занят → любой свободный
- `POST /api/probe {link, session_id?}` → запись; сразу стартует спекулятивная загрузка всего аудио
- `POST /api/jobs {links, session_id?, format, quality, from, to, tracks[]}` → `{ids}`; ссылки через пробел = пакет
- `GET /api/state` → probe (с прогревом), текущая/последняя задача (этап, %, скорость, ETA, ×реального времени, дорожки, гистограмма, p50/p99), `queued`, история
- `GET /api/jobs/{id}/audio` — растущий поток MP3/Opus во время сведения, после — файл потоком с Range (`files.rs`, `bytes=a-b | a- | -n`, 416 за концом)
- `POST /api/jobs/{id}/cancel`, `POST /api/reveal {path}` (только пути, созданные приложением)
- история: `<кэш>/history.json`, 50 записей, без session-id

## ИНВАРИАНТЫ
- слушать только 127.0.0.1
- один `Engine` на session-id: потолок 256 соединений общий для всех задач и спекулятивных загрузок
- задачи выполняются по одной, по порядку; «ещё N в очереди»
- при старте задачи загрузка урезается до её отрезка и дорожек (`Download::restrict`) — лишнее не качается
- session-id живёт только в памяти, в историю и логи не попадает

# Оркестрация и дисциплина правок

§2 канона v23, блок владельца №2 (журнал `docs/resheniya/resheniya.md`).

## Оркестрация

**ОД-1.** Контекст агенту передаётся файлами: задание — отдельный файл задания с путями к входам; состояние этапа — файл state/<этап>.md; агент не получает историю диалога и не читает план целиком, только свой раздел. Выход этапа — файл, следующий этап получает путь.

**ОД-2.** Один агент — одна задача, один результат, одно владение файлами (список путей в задании). Писать вне своего списка запрещено. Параллельно — не более 3–5 агентов; при большом числе элементов — пакеты по 5–10 на агента, не агент на элемент.

**ОД-3.** Роли разделены: автор реализации не меняет тесты; проверяющий не меняет код (только читает, запускает, пишет отчёт и подложенные ошибки в отдельной копии); главная сессия сливает только после собственного перезапуска проверок.

**ОД-4.** Ответ агента главной сессии — не длиннее 500 слов: сделано / не сделано / проверено / отступления / решения. Всё остальное — в файл отчёта с путём.

**ОД-5.** Повторы ограничены: этап с валидатором перезапускается не более 3 раз, затем останавливается с отчётом об ошибке.

**ОД-6.** Расследование отделено от починки: пока причина не названа и не воспроизведена тестом, правки и коммиты запрещены; гипотезы перечисляются все, проверяются по очереди, отбрасываются явно.

**ОД-7.** Агент, исчерпавший контекст, заменяется новым через файл передачи; главная сессия не доделывает его работу сама.

## Дисциплина правок

**ОД-8.** Сначала план, потом код: для нетривиальной задачи — план с критериями успеха (гейтами) до первой правки.

**ОД-9.** Хирургические правки: меняется только то, что требует задание; несвязанный код, комментарии, форматирование не трогаются; «улучшения по пути» запрещены — они отдельное задание.

**ОД-10.** Простота: предпочитать короткое решение длинному; не добавлять абстракций, флагов, режимов и параметров «на будущее»; мёртвый код удалять, а не оставлять под флагом.

## Дополнения v23

**§2+1.** Бюджет агента: при ~300k токенов агент обязан написать передачу; главная сессия не продлевает агента выше этого порога.

**§2+2.** Файл задания агенту содержит: цель, владение (пути), входы (пути + хэши), гейты, что запрещено читать, формат отчёта, лимит процессов. Ничего сверх этого — план и чужие результаты агент не видит.

**§2+3.** Модели по ролям: оркестратор и архитектура — сильная модель; реализация — средняя; ревью и валидаторы — быстрая, с большим входом и коротким выходом.

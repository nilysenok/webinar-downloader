# Данные и информационное множество

§3 канона v23 и ОД-11, ОД-12 (блок владельца №2). В этом проекте (загрузчик записей) рядов, бэктестов и тестовых наборов нет: пункты действуют, когда такие данные появятся; применимое здесь — в `mutations.md`.

**§3.1.** **Проверка сдвига обязательна для каждого входного ряда** до первого использования и после каждой регенерации: корреляция с целевой величиной при сдвигах −2…+1, максимум должен быть на последнем известном дне; для оконных рядов — по приращениям; для рядов с плоским профилем — вторая проверка через связанную величину. Результат — первая строка журнала шага. Ряд без проверки в расчёт не входит (хук на загрузку данных проверяет наличие отметки).

**§3.2.** **Лаг исполнения по умолчанию.** Решение на закрытии дня d исполняется не раньше d+1 (или по закрытию d, если это явно объявлено и обосновано). Тест «исполнение в том же баре, что и сигнал» обязан падать.

**§3.3.** **Point-in-time.** Любой ряд хранится с датой, когда значение стало известно (решение ЦБ ≠ вступление в силу; отчётность ≠ дата периода; пересмотры данных — отдельными версиями). Календарь торгов, остановки, корпоративные события — отдельные файлы с хэшами.

**§3.4.** **Константа в данных — ошибка, пока не доказано обратное.** Любая подстановка (ffill, bfill, среднее, ноль) на отрезке длиннее одного наблюдения требует отметки в журнале и теста, что она не влияет на результат.

**§3.5.** **Ключ кэша = хэш всех входов и кода.** Ряды, параметры, версия кода, конфиг. Проверка: подмена любого входа при том же ключе обязана давать промах кэша (тест с мутацией).

**§3.6.** **Эталонные таблицы** (golden) для каждого этапа пайплайна; после исправления ошибки старые — в архив с хэшами и причиной, новые генерируются с исправленного кода; сверка побайтно или с допуском, объявленным заранее.

**§3.7.** **Одно определение на метрику** на весь проект (например, ddof, годовая шкала, база избыточной доходности). Два определения в одной таблице запрещены; смена определения — PR с пересчётом всех таблиц и строкой «что изменилось».

## Из блока 2

**ОД-11.** Никаких режимов, воспроизводящих исправленные ошибки: старые результаты — в архив с хэшами, эталоны пересчитываются на исправленном коде.

**ОД-12.** Каждое изменение данных, ключей кэша, параметров по умолчанию — отдельный PR с тестом, который падает без правки, и строкой «что изменилось в числах».

Умолчание по ПР-16 (27.10): в проектах, где работают прямо в `main` без PR, «отдельный PR» = отдельный коммит с этим тестом и строкой «что изменилось в числах».

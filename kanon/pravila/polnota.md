# Полнота работы

§1 канона v23, блок владельца №1 (журнал `docs/resheniya/resheniya.md`). Раздел обязателен для главной сессии и всех агентов, включается в каждое задание агенту целиком.

## A. Гейты до работы

**ПР-1.** До начала любой нетривиальной задачи агент пишет файл гейтов `GATES.md` в своём рабочем каталоге: список наблюдаемых результатов G1…Gn, у каждого — `CHECK:` (команда, которая проверяет результат), `EXPECT:` (ожидаемый вывод или значение), `EVIDENCE:` (фактический вывод; до запуска — `pending`). Один гейт — один результат. Ручной гейт (без команды) допустим, только если проверку нельзя выразить командой; это пишется явно.

**ПР-2.** Гейты покрывают каждое независимое требование задания. Требование без гейта — повод вернуть задание на уточнение, а не пропустить его.

**ПР-3.** Тривиальные правки и фактические ответы гейтов не требуют.

## B. Исполнение

**ПР-4.** Задание выполняется целиком. Нет заглушек, «TODO», «остальное аналогично», «упрощённой версии». Если часть невозможна — гейт помечается `ABANDON: <id> <причина>`, и это выносится в отчёт первой строкой; удалять или переписывать гейт задним числом нельзя.

**ПР-5.** Файлы читаются полностью; код, который меняется, читается вместе с местами вызова.

**ПР-6.** Любое отступление от задания (сетка, выборка, число повторов, метод, пропущенный шаг) — отдельной строкой «отступление» с причиной, до выводов. Молчаливое упрощение — нарушение.

**ПР-7.** Запреты не обходятся «для скорости»: запрещённые файлы не читаются, замки не снимаются, запрещённые команды не выполняются. Мешает — доложить.

**ПР-8.** Ошибка или странный результат — разбор до причины, не подавление симптома (try/except, фильтр строк, подмена значения).

**ПР-9.** Четыре прохода по результату: (1) сделать полностью; (2) перечитать как эксперт и заменить каждое слабое место; (3) искать дефекты корректности, интеграции, производительности и доказательств — исправить; (4) повторять, пока проход ничего не находит.

## C. Доказательства и отчёт

**ПР-10.** Гейт закрыт, только если команда CHECK выполнена, код возврата 0 и вывод совпал с EXPECT; вывод записан в EVIDENCE. Галочка без вывода = не закрыт. Самооценка «проверил, работает» доказательством не является.

**ПР-11.** Все числа в отчёте перемеряются в момент написания отчёта и берутся из файлов или выполненных команд с указанием источника. Оценки «примерно» допустимы только там, где измерить нельзя, и помечаются отдельно.

**ПР-12.** Отчёт «готово» запрещён, пока есть незакрытые, отложенные или ABANDON-гейты, или вопрос, ждущий решения владельца. Тогда отчёт называется «передача» и начинается с перечня незакрытого.

**ПР-13.** Отчёт пишется для того, кто не видел работы: сделано / не сделано / проверено (какими командами) / отступления / требует решения. Без пересказа задания и общих слов. Реестр гейтов «закрыто N из M» обязателен.

**ПР-14.** Главная сессия перед слиянием сама перезапускает CHECK-команды листа (перепроверка родителем), а не верит отчёту; при расхождении результат возвращается агенту, а не доделывается главной сессией молча.

## D. Контекст и разбиение

**ПР-15.** Большая задача разбивается на листы с собственными гейтами и явным владением файлами; у ветки — интеграционные гейты (совместимость листов, сквозной прогон, регрессии). Разбиение — до распараллеливания.

**ПР-16.** Вопрос владельцу — только если без ответа работа невозможна или необратима; иначе разумное умолчание, записанное явно.

**ПР-17.** При признаках исчерпания контекста (повторное чтение тех же файлов, потеря деталей задания) агент пишет файл передачи и просит замену, а не доделывает «как получится». Занижать оставшийся контекст и сворачивать работу раньше времени — тоже нарушение.

## Связь с главным файлом канона

Раздел ничего не отменяет, он дополняет:
- «Ритм сессии → По ходу: сначала план, потом код» — план включает гейты с командой проверки (ПР-1…3, ОД-8); прошедшие тесты закрывают гейт, только если их вывод записан в EVIDENCE (ПР-10).
- Закон 7 «Критерий остановки пишется заранее» — тот же принцип для любой нетривиальной задачи: EXPECT пишется до работы (ПР-1).
- Закон 3 «Ничего не выдумывать» — числа в отчёте перемеряются в момент отчёта и несут источник (ПР-11).
- «Ритм сессии → Конец, п. 3»: зелёный валидатор — один из гейтов, а не замена им; отчёт «готово» — только при всех закрытых гейтах (ПР-12).
- «Ритм сессии → Конец, п. 6» (`/clear`) — при исчерпании контекста сначала файл передачи, потом замена (ПР-17, ОД-7).
- «Ритм сессии → По ходу: одна сессия — один модуль» — крупная задача делится на листы с владением файлами и интеграционными гейтами (ПР-15, ОД-2).
- Закон 3, `❓` в ОТКРЫТО — остаётся для неизвестных фактов; для решений действует ПР-16.

## Ж-004 · полнота и задание агенту (Э2)

**Ж4-2.1.** `templates/GATES.md` — формат: `- [ ] G<n>: <результат>` / `CHECK: <команда>` / `EXPECT: <вывод>` / `EVIDENCE: pending`. Правила [Т]: один гейт — один наблюдаемый результат; ручной гейт только если нельзя выразить командой, с пометкой `MANUAL:`; галочка без EVIDENCE = не закрыт; `ABANDON: G<n> <причина>` вместо удаления.

_Здесь: [Ш+Х] `templates/GATES.md` в этом формате; хук Stop понимает оба формата гейтов («G1 — …» и «- [ ] G1: …»)._

**Ж4-2.2.** `templates/zadanie_agentu.md` — обязательные поля, валидатор `scripts/kanon/validate_zadanie.py` [Ш+Х: хук SubagentStart / проверка перед запуском агента отказывает при пустом поле]:
1. Blok (Ж-NNN) и пункт постановки.
2. Цель: что и зачем (спецификация). Отдельно — план: как (агент не меняет спецификацию).
3. Владение: список путей, которые можно создавать/менять. Всё остальное — только чтение.
4. Запрещено читать: [ТЕСТОВЫЕ_ПУТИ], чужие отчёты, план целиком (перечислить).
5. Входы: пути и SHA-256 каждого.
6. Гейты: ссылка на GATES.md агента (создаётся до работы).
7. Пять вопросов автономного прогона: что такое «готово»; чем проверить; что можно трогать; что остановит (лимит токенов, повторов, процессов, времени); кто подписывает результат.
8. Лимиты: процессов ≤ N, токенов ≤ 300k, повторов ≤ 3, ответ главной сессии ≤ 500 слов.
9. Формат отчёта: `templates/otchet_agenta.md`.
10. Уверенность агента 1–10 после прочтения задания и что её снижает (пишется агентом в первые 5 минут, до работы).

_Здесь: [Ш+Х] `templates/zadanie_agentu.md`; валидатор `scripts/kanon/validate_zadanie.py` (тесты `tests/test_kanon.py`); хук PreToolUse на запуск агента — отказ, если задание не по шаблону (SubagentStart блокировать не умеет)._

Без пересказа задания, без самооценки. Не длиннее 500 слов; остальное — в файл.
